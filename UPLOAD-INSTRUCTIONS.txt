OpalDay app v1.6.2 + Cloudflare Worker v1.5.13 — audit remediation release
(overlap-safe pushes, true two-channel med reminders, bounded history, backup)

DATA SAFETY
This release keeps the existing local-storage key (opalday-data-v1), sync-code
key, Cloudflare D1 database, sync endpoint, calendar IDs, item IDs, event IDs,
completion history, reminder settings, visibility settings, recurrence data,
all-day dismissal markers, and deletion tombstones unchanged.

No SQL migration is required. Do not recreate or replace the D1 database.
D1 is read-only for user data: the worker only adds schema columns/tables
(status on notification_log, push_ack, sync_attempts) and inserts new rows.
The VAPID private key now lives in the VAPID_PRIVATE_JWK worker secret
(a JSON private JWK), never in the repo.

GITHUB PAGES
Upload all top-level app files to the root of the OpalDay repository, replacing
files with the same names:
  index.html, app.js, calendar.js, notifications.js, config.js, sw.js,
  styles.css, calendar.css, v04.css, manifest.webmanifest,
  app-icon.png, app-icon-180.png, app-icon-192.png, app-icon-512.png
The worker.js file is also committed here for reference, but GitHub Pages does
not serve it.

When releasing a new app version, ALL of these must move together or the app
breaks: OPALDAY_VERSION in app.js, APP_VERSION in sw.js (drives the cache name
and every asset ?v=), the ?v= parameters in index.html, and the About version
in index.html. The old cache is purged automatically on activation.

CLOUDFLARE WORKER
Deploy worker.js as the `opalday` worker script (account b35ff435ff24d134ff640e0099dd13fc),
preserving the existing D1 binding (DB -> 807f15fa-e116-4b93-95cd-bf4a6663d934),
the existing secrets, and the existing cron trigger (*/1 * * * * — every minute).
Compatibility date is currently UNSET; keep it unset.

Secrets on the worker (send type "inherit" for all existing ones when
deploying, so their values carry forward untouched):
  VAPID_PRIVATE_JWK  — secret_text, a JSON VAPID private JWK
                       {"kty":"EC","crv":"P-256","x":"...","y":"...","d":"..."}
                       Set this on the first deploy; "inherit" afterwards.
If VAPID_PRIVATE_JWK is missing, the cron run logs last_cron_error
("VAPID_PRIVATE_JWK secret is missing") in /health and sends nothing.
